# How the calculation was recovered

The initial problem was an RNS315 that expects a CID-dependent CMD42 password. The available blog demonstrated observing a radio's answer, but did not publish a general calculation rule. This project instead examined an existing local firmware-update ISO.

## Source identity

| Artifact | Bytes | SHA-256 |
|---|---:|---|
| EU 1508/0270 ISO | 40,540,160 | `e10fa6be5eb3a7a271415bd508c2f79054c4bb6b7343e7e7056bc76fd1a3294f` |
| Main DAT | 40,168,980 | `76f10b5f79f7abef1decd0898bb877acd461ea367661aedeb9b4f8b243a7db71` |

The ISO contains the update index and `VW_EU_1508-0270-IC502-121123.dat`. The hashes identify the analyzed bytes; they do not authenticate the publisher. No firmware or map payload is distributed here.

## Packing layers

The DAT divides into 68 observed update records. Two records contain word-byte-swapped Blackfin program streams. Their 27 and 122 frames parse exactly to EOF and all 149 internal checksums match.

A frame has the little-endian header `uint16 type, uint16 checksum, uint32 address, uint32 size`. Type 3 carries raw bytes. Types 4 and 5 carry a size expressed in 16-bit words. Other observed types carry no input payload. Type labels beyond their observed structure remain partly inferred.

Type 4 uses word LZSS. A 16-bit LSB-first control word selects 16-bit literals or references. For a reference token, byte distance is `((token & 0xfff) + 1) * 2`; byte length is `((token >> 12) + 2) * 2`.

Type 5 adds an XOR mask generated by RC4. The 256-byte outer metadata record of type `0x8005` is the RC4 key. One RC4 byte is duplicated across both bytes of each word and applied to each group of 17 packed words: a control word and its 16 tokens. The stream continues across type-5 frames and resets for each program stream. The recovered keystream matched 100 previously reconstructed mask bytes before the complete decoder was applied.

This recovered all 30 program payload frames: 17,915,032 bytes in the main stream and 1,245,686 bytes in the secondary stream, with no invalid LZ references. The analysis ELF wrappers preserve the decoded load addresses; their section permissions are analysis choices, not observed firmware permissions.

Resource records use a different format: cumulative LE32 deltas, a page-end table and independent 4 KiB byte-LZSS pages. Fifteen resources decoded with exact declared sizes. Two resource boundaries remained unresolved by one and two bytes; they are not needed for the calculator and no missing bytes were invented.

## SD-driver call path

The relevant function is `0x0017C158`. Its caller at `0x0017AEFC` supplies the CID from the SD state and the selected configuration. The same caller constructs a CMD42 request and passes command `0x2a` at `0x0017AF2A`.

The default descriptor is installed into the SD object at `0x001754C2` and points to `0x00236A60`. It contains four all-one masks, four addends, password length 16 and a flag enabling MD5.

The machine code computes four words as `(cid_word & mask_word) + addend_word`, wrapping at 32 bits. It hashes the resulting 16 little-endian bytes with the standard MD5 implementation and returns a length-prefixed password. The calculator exposes the 16 password bytes without that transport length prefix.

The supplied CID end byte needs normalization. Recomputing CRC7 from the first 15 bytes and clearing the final end bit matches the privately held result and all ten current published examples, including examples whose host-provided final byte was `00`. The original recovery used two public guide pairs; the eight later external pairs were checked without changing the calculation. Discarding CRC7 entirely produces the wrong answer.

## Analysis tools and attribution

- [Ghidra](https://github.com/NationalSecurityAgency/ghidra), version 12.1.4, with JDK 21.0.10.
- [geepot/ghidra-blackfin](https://github.com/geepot/ghidra-blackfin), commit `f417b090cda3e04fa17a8843f0fc9001c7804053`, GPL-3.0-or-later. The module was built in an isolated analysis environment and is not bundled here.
- [pypcode](https://github.com/angr/pypcode), version 4.0.1, for static decoding using that processor specification.
- [Danman's RNS315 experiment](https://blog.danman.eu/updating-rns315-maps-for-fun-and-profit/) and [source](https://github.com/danielkucera/esp32-sdcard), which established the observation-based route and provided useful protocol context.
- [corecode/sdlock](https://github.com/corecode/sdlock), another independent description of observing CMD42 and operating on a card with an already known password.

The calculator is a new implementation of the recovered mathematical transformation. Decompiled firmware, the processor module, proprietary map data and the owner's private test pair are not included.
