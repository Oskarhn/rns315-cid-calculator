# What I've tested

## Two working SD cards

I've prepared **two SD cards** with this method and checked that **both work in my RNS315**. That includes the physical setup: reading each card's CID, preparing it with the matching password and using it in the radio.

These were real cards in my own setup. I haven't put their private CIDs or passwords in this repository. The examples in the guide use public values instead.

## Public CID/password examples

I also compared the calculation with CID/password pairs I found publicly. The test set contains **ten different CID payloads**, and the calculated password matches every expected value on all **16 bytes**.

The expected values come from those published pairs, rather than being generated by the calculator being tested. They're stored as SHA-256 fingerprints of the binary password bytes in [the test fixture](../tests/fixtures/public-cid-password-pairs.json).

[Sources for the public examples](public-test-vectors.md) explains where they came from. Five of the eight additional pairs were presented as card examples; three were published demonstration values. Several came from the same contributor, so ten pairs doesn't mean ten independent authors or ten physical cards.

## The password I bought

Before the calculation was recovered, I bought a password for my own card. The calculator produced the same value. That gave the project another comparison point alongside the public examples.

## Software checks

The Python and JavaScript implementations are checked separately. The automated checks cover:

- The public CID/password pairs and CRC normalization.
- Known CRC7 and MD5 values, plus invalid and oversized input.
- Firmware decoding helpers using small, known inputs.
- Serial framing, errors and timeouts.
- The browser interface, saving the password, mobile layout and a simulated ESP32 connection.

The ESP32 program also builds in GitHub Actions. Those software checks support the two card tests; they exercise different parts of the project.

To run the checks yourself, see [development.md](development.md). To make your own card, start with the [map update guide](update-maps.md).
